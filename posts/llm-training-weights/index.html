What happens inside an LLM
when it learns something

Gradient descent, backpropagation, and how facts, relationships, and language patterns get encoded as billions of floating-point numbers. What it means for a model to "know" something — with no memory address, no database, no filing system.

There is a question that most people never think to ask, and once you hear it you cannot unhear it: when an AI model "knows" that Paris is the capital of France, where exactly does that knowledge live?

It is not in a database. There is no row in a table that says France → Paris. It is not indexed anywhere. There is no pointer, no memory address, no filing cabinet. The knowledge is encoded — smeared, really — across hundreds of billions of floating-point numbers, distributed through layers of a neural network in a way that nobody fully understands, including the people who built it.

This fact has enormous consequences for everything we will discuss in this series. Before we can understand why AI memory is broken, why current solutions all eventually fail, and why a new approach might be necessary — we need to understand this: how does a language model actually learn something in the first place?

This post answers that question from the ground up. No prior machine learning knowledge required. But we will not shy away from the technical details that matter.

🗺
What this post covers
We start with what an LLM is at its most basic level — a prediction machine with billions of tunable numbers. Then we walk through exactly how training works: forward passes, loss functions, backpropagation, and gradient descent. We end with what recent research has revealed about where different types of knowledge actually live inside the network. By the end, "the model knows X" will mean something precise to you — and that precision will matter for every post that follows.

A prediction machine with a memory problem

Let's start with the simplest possible description of a large language model: it is a function that takes a sequence of words (technically tokens) and predicts what word should come next.

That's it. The entire enterprise of GPT-4, LLaMA, Claude, Gemini — all of it, at the most fundamental level, is a sophisticated version of autocomplete. Given "The capital of France is", the model produces a probability distribution over every possible next word. "Paris" should have a very high probability. "Banana" should have an extremely low one.

Everything a language model can do — answer questions, write code, reason through problems, hold a conversation — emerges from this single training objective, applied at enormous scale over vast amounts of text. The objective is called next-token prediction, and it is the reason these models know as much as they do.

Figure 1. The fundamental operation of a language model. Given a sequence of input tokens, the model outputs a probability distribution over every possible next token. The entire training process is about making this distribution as accurate as possible.

Now here is the key question: how does the model learn to produce "Paris" with 96% probability from the input "The capital of France is"? It did not start out knowing this. At the beginning of training, it knows nothing. Its weights are initialised with small random numbers. It would produce garbage. The process of going from random garbage to a model that can answer almost anything coherently is called training, and it is one of the most remarkable engineering achievements in human history.

The architecture: a deep look at what's actually inside

Before we can understand training, we need to understand what is being trained. A modern LLM is built on an architecture called the Transformer, introduced by Google researchers in the 2017 paper "Attention is All You Need" — one of the most-cited papers in the history of computer science, with over 173,000 citations as of 2025.

A Transformer processes text through three major components stacked in sequence. Understanding each one is essential to understanding where knowledge lives.

Figure 2. The three core components of a Transformer. Embedding layers convert tokens to vectors. Self-attention layers capture relationships between tokens. Feedforward networks act as key-value memory stores for factual knowledge. Each modern LLM stacks dozens to hundreds of these layers.

Component 1: The embedding layer

Every word (or sub-word token) in the model's vocabulary is mapped to a dense numerical vector — typically 512 to 4,096 numbers long. GPT-3, for example, uses 12,288-dimensional embeddings. These vectors are learned during training, not hand-crafted. Related concepts end up close together in this high-dimensional space: "king" and "queen" are nearby; "Paris" and "France" are nearby; "dog" and "cat" are nearby.

Component 2: Self-attention layers

This is the mechanism that made Transformers revolutionary. Every token in a sequence gets to "look at" every other token and decide how relevant it is. The famous query-key-value mechanism works like this: each token generates three vectors called a Query (what am I looking for?), a Key (what do I contain?), and a Value (what information do I have to offer?). Attention scores are computed by comparing each token's query against all tokens' keys, then using those scores to create a weighted combination of values.

The mathematical formula is elegant:

Scaled Dot-Product Attention
Attention(Q, K, V) = softmax( QKᵀ / √d_k ) · V
Where Q, K, V are the query, key, and value matrices, and d_k is the dimension of the key vectors. Dividing by √d_k prevents the dot products from becoming so large that gradients vanish.

Modern LLMs run this attention operation in parallel across multiple "heads" — typically 8 to 96 heads depending on the model. Each head learns to attend to different types of relationships: one might track subject-verb agreement, another might track coreference (which pronoun refers to which noun), another might capture long-range semantic dependencies. The original 2017 Transformer paper showed this "multi-head" approach consistently outperformed single-head attention.

Component 3: Feedforward networks (FFN)

After attention, each token's representation passes through a feedforward neural network — essentially two linear transformations with a non-linear activation (typically ReLU or GELU) in between. This component is much less discussed than attention but, as we will see shortly, is where most of the model's factual knowledge actually lives.

Modern LLMs stack these three components — embedding, attention, FFN — dozens or hundreds of times. GPT-3 has 96 such layers. The total number of parameters is staggering.

175B parameters GPT-3 (2020)
~1.8T parameters GPT-4 (est., 2023)
400B total params Llama 4 Maverick (2025)

Each of those parameters is a single floating-point number — a weight. Training is the process of finding the right values for all of them.

How training actually works: the forward pass

Let's walk through training step by step, using a concrete example. Suppose the model is being trained on a sentence from Wikipedia: "The Eiffel Tower is located in Paris."

The model is shown the partial sequence "The Eiffel Tower is located in" and asked to predict the next word. Before any training has happened, it predicts something useless — maybe "the" or "a" or random noise. The correct answer is "Paris".

A forward pass is the process of running the input through the entire network from beginning to end to produce this prediction. The input tokens flow through the embedding layer, then through all the attention and FFN layers in sequence, and finally through a classification layer that converts the final representation into a probability distribution over the entire vocabulary.

Figure 3. The forward pass. Input tokens flow left-to-right through all Transformer layers sequentially, each layer refining the representation. The final layer's output is converted to a probability distribution over the vocabulary via softmax. In GPT-3, this happens across 96 layers.

Once the forward pass produces a prediction, we need to measure how wrong it was. This is done using a loss function — specifically, for language models, cross-entropy loss. The loss is a single number that captures the gap between the model's prediction and the correct answer. If the model assigned "Paris" a probability of 96%, the loss is low. If it assigned "Paris" a probability of 0.01%, the loss is very high.

The goal of training is to minimise this loss across every training example — ideally trillions of them.

Backpropagation: running the learning signal backward

We have a loss. Now we need to figure out which of the billions of weights contributed to that loss, and by how much. This is where backpropagation comes in.

Backpropagation is an algorithm for efficiently computing the gradient of the loss with respect to every weight in the network. The gradient is just the partial derivative — a number that tells you: "if I increase this weight by a tiny amount, how much does the loss change?" A positive gradient means increasing the weight increases the loss (bad — decrease it). A negative gradient means increasing the weight decreases the loss (good — increase it).

The reason backpropagation is computationally efficient is the chain rule of calculus. Because the network is a composition of functions — one layer feeds into the next — the gradient at any layer can be computed by multiplying the gradient from the layer above by the local derivative at the current layer. This "chain" of multiplications can be computed in a single backward pass through the network, exactly mirroring the forward pass but running in reverse.

Figure 4. Forward and backward passes in training. The forward pass (green, left-to-right) computes the prediction. The backward pass (red, right-to-left) propagates gradients back through every layer using the chain rule. Each weight is then updated by subtracting a small fraction of its gradient.

⚠️
The memory cost of gradients
During training, you need to store not just the model weights but a gradient for every single weight. For a 7-billion-parameter model, that means 7 billion additional numbers — about 28 GB just for gradients (at 32-bit float precision). The optimizer (usually AdamW) adds two more quantities per weight, bringing the total training memory for a 7B model to roughly 112 GB. This is why training large models requires clusters of expensive GPUs.

Gradient descent: finding the valley in a billion-dimensional landscape

Knowing the gradient is not enough. We also need to decide what to do with it. The answer is an algorithm called gradient descent.

The intuition is geometric. Imagine the model's loss as a surface in an unimaginably high-dimensional space — one dimension per parameter. At any point on this surface, the gradient tells you which direction is "uphill". The algorithm takes a small step in the opposite direction — downhill — aiming to find the lowest point (minimum loss). At the lowest point, the model makes the best possible predictions.

The size of each step is controlled by the learning rate, one of the most important hyperparameters in training. Too large and the model overshoots the minimum and oscillates wildly. Too small and training takes forever. Modern training schedules start with a warmup phase (gradually increasing the learning rate), then use cosine annealing (gradually decreasing it over time) to achieve stable, efficient convergence.

Figure 5. A 2D simplification of the loss landscape. Training starts with random weights (red dot, high loss) and gradient descent takes iterative steps toward the minimum. In reality, this space has billions of dimensions — but the principle is identical: always move in the direction that reduces loss.

In practice, large models are not trained on one example at a time. They use mini-batch gradient descent: process a batch of hundreds or thousands of examples simultaneously, average the gradients across the batch, and perform a single weight update. This provides more stable gradient estimates and takes full advantage of GPU parallelism.

Most modern LLM training uses the AdamW optimizer — an extension of gradient descent that keeps a running estimate of both the average gradient and the average squared gradient for each weight. This allows different weights to have adaptive, individual learning rates, which dramatically accelerates convergence compared to vanilla gradient descent.

"In training a 7B-parameter LLM on 15 trillion tokens, gradient descent runs approximately 1.5 million weight updates — each one nudging all 7 billion numbers infinitesimally closer to their optimal values."

What training data looks like: the scale problem

For gradient descent to find meaningful patterns, it needs to see an enormous amount of text. Language is infinitely complex — full of idiom, ambiguity, cultural reference, implicit structure, and context-dependence. A model that has seen only 1 million sentences will have terrible generalization. One that has seen trillions of sentences, drawn from books, articles, code, conversations, and scientific papers across every domain, begins to approach something that looks like general understanding.

The relationship between model size, training data, and performance is governed by what researchers call scaling laws. The landmark 2022 Chinchilla paper from DeepMind established that for optimal performance, you should train roughly 20 tokens per parameter. This means a 70B-parameter model should ideally be trained on 1.4 trillion tokens. Meta's Llama 3, released in 2024, trained its 8B model on 15 trillion tokens — far beyond Chinchilla-optimal — because smaller, longer-trained models are cheaper to deploy at inference time. By 2025, Llama 4's Maverick model was trained on over 30 trillion tokens.

2T tokens Llama 2 training (2023)
15T tokens Llama 3 training (2024)
30T+ tokens Llama 4 training (2025)

What does this mean concretely? Llama 3's 15 trillion tokens is roughly equivalent to 11 million books, or about 150 times the size of the entire English Wikipedia. The model encountered each of these tokens, computed a loss, ran backpropagation, and nudged every one of its billions of weights slightly in response. Training the flagship Llama 3 model used approximately 3.8 × 10²⁵ floating-point operations — 50 times more compute than Llama 2.

Where knowledge actually lives: the surprising answer

This brings us to the most interesting question: after all of this training, where exactly does the model's knowledge live? When the model knows that the capital of France is Paris, which weights encode that fact?

The answer, which has been the subject of active research since 2021, is surprisingly specific: factual knowledge is primarily stored in the feedforward (FFN) layers, particularly in the middle-to-late layers of the network.

A landmark 2021 paper by Geva et al. showed that the FFN layers in Transformer models function as key-value memories. Each neuron in the FFN layer stores a pattern (the "key") and a value (what to output when that pattern is detected). When "France" appears prominently in the context, certain FFN neurons activate that store France-related facts, including its capital city.

Figure 6. What different layers of a Transformer learn during training, based on research by Geva et al. (2021), Meng et al. (2022), and Lv et al. (2024). Factual associations — including world knowledge like capitals, dates, and named entity relationships — are primarily encoded in the middle FFN layers. Later attention layers help propagate this information to the output.

This finding was confirmed and extended by Meng et al. (2022) in a paper called ROME (Rank-One Model Editing), which showed that you can surgically edit a model's knowledge of specific facts by modifying weights in specific FFN layers — effectively performing a targeted "memory rewrite" on the model. This work was direct evidence that factual knowledge has a physical location inside the network, even if that location is distributed across many neurons.

More recent research from Lv et al. (2024) has described the factual recall process in three stages: (1) early attention heads extract the subject entity ("France") from the context; (2) that information activates relevant FFN neurons in middle layers; (3) the activated FFN neurons redirect the model toward the correct answer ("Paris").

🔬
Key research finding
Recent Stanford Hazy Research work (late 2025) showed that LLMs store facts at a rate that scales near-linearly with parameter count — more parameters means proportionally more facts storable. This capacity scales roughly at the information-theoretic lower bound, suggesting Transformers have evolved a near-optimal strategy for fact storage despite never being explicitly designed for it.

It is also important to note what attention layers store versus FFN layers. Research suggests attention weights capture primarily relational structure — how words relate to each other, grammar, syntax, coreference — while FFN weights store the factual content itself. The two types of knowledge are architecturally separated, which has significant implications for how models fail and how they might be improved.

The three training phases that shape modern LLMs

Training a modern LLM is not a single process. It has three distinct phases, each with a different objective:

Phase Objective Data What it produces
Pre-training Next-token prediction Trillions of tokens from the internet, books, code A model that knows enormous amounts about the world, but doesn't know how to behave helpfully
Supervised Fine-tuning (SFT) Match human-written responses Thousands to millions of human-labelled prompt-response pairs A model that follows instructions and formats answers helpfully
RLHF / RLAIF Maximise human preference scores Human rankings of model outputs A model aligned with human preferences for helpfulness, harmlessness, honesty

The critical insight here: most factual knowledge enters the model during pre-training. Fine-tuning teaches the model how to use its knowledge — to answer questions, follow formats, stay on topic — but it contributes relatively little new factual knowledge. Research by Gekhman et al. (2024) found that instruction tuning is better characterised as a form of self-alignment with the model's existing internal knowledge, rather than knowledge acquisition. Once pre-training ends, the knowledge in the model is largely frozen in place.

This is the first hint of the memory problem that this series is about. Training encodes a snapshot of the world at a point in time. The weights are fixed. There is no mechanism for the model to learn that something has changed. The world moves on; the model does not.

Why this is not how human memory works

There is a temptation to draw analogies between the way LLMs learn and the way human brains learn. The analogy has some basis — both involve distributed representations, both involve something like gradient-based weight adjustment (Hebbian learning in the brain), and both show emergent structure from repeated exposure. But the differences are profound, and understanding them matters for the rest of this series.

When a human learns a new fact — say, that a colleague got married last weekend — that fact is encoded in a specific, locatable memory trace via hippocampal consolidation. It can be updated, corrected, forgotten, and retrieved selectively. The rest of the brain's knowledge is not disrupted. The newly learned fact can be related to prior knowledge through effortful cognitive processing.

When an LLM "learns" — during pre-training — every weight in the network is nudged in response to every piece of training data, simultaneously. There is no localised memory trace. The knowledge about France and the knowledge about chemistry and the knowledge about poetry are all encoded in the same distributed soup of weights, all interfering with each other, all subject to the same training dynamics. There is no "add a new fact" operation. There is only "retrain everything".

This is the root cause of a problem we will explore in depth in a later post: catastrophic forgetting. When you fine-tune a model on new information, the gradient updates that reinforce the new knowledge can destructively interfere with the weights that held old knowledge. You teach the model about recent events; it forgets things it knew before. This is not a bug that can be patched — it is a consequence of how distributed weight-based learning works.

💡
The key distinction to carry forward
An LLM's knowledge is parametric — encoded in weights, distributed across the network, fixed at training time. It has no concept of "a specific memory" — just probabilities shaped by everything it has ever seen. This is fundamentally different from a database, a filing system, or human episodic memory. Everything in this series flows from this distinction.

What comes next

We now have a precise understanding of what an LLM learns during training. But training only happens once — or infrequently. After that, the model is deployed for inference: real users, real conversations, real questions, all of which happen in real time without any weight updates.

So how does the model "remember" things within a conversation? The answer involves the context window — and the context window is not memory in any sense we normally mean. It is something stranger, more limited, and more consequential than most people realise.

That is the subject of the next post.
